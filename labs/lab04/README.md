Данная лабораторная работа посвещена практическому анализу и определению мер снижения рисков ИБ. То есть вам, при развитии компетенций в ИБ, будет требоваться доносить требования ИБ, необходимость их выполнения, критичность и важность до коллег. 

Аналогичным образом, с помощью данного практического задания будет понятно на сколько плотно вы взаимодействовали с ИБ, что знаете из основ по обеспечению защиты информации, а также с какими подобными кейсами вы сталкивались в своей практике.

Вы получите навыки оценки задачи в роли специалиста ИБ, посмотрите на кейсы со стороны ИБ и сможете дать свою оценку, как бы вы подошли к этим вопросам в данной ситуации.

## Вводные

Компания зарегистрирована в Евросоюзе и должна соответствовать законодательству ЕС. Работая в данной компании занимаетесь обеспечением ИБ. 

Вы обнаруживаете админскую консоль веб-сайта своей компании, которая доступна неограниченному кругу лиц в сети Интернет, так как публикация торчит во внешний сегмент сети
> - С помощью её интерфейса доступны на просмотр записи с запросами о приобретении продукции компании, которые содержат персональные данные, а также коммерческие предложения (что, в каком объёме, за сколько, специальный условия и т.д.). 
> - Аналогично доступны логи, в которых видны ip-адреса администраторов, которые попадали в нее.

## Предоставление материалов

> - Ожиается результат в виде аналитической записки на `gist`, которая будет раскрывать уровень, степень критичности рисков, меры, которые могут снизить этот риск, приоритет, подход.
> - Необходимо иметь в наличии проведенный анализ рисков, их описание, меры снижения рисков, техническое решение. Данные материалы должны быть, как минимум, описаны технически, включая пояснения для менеджмента. Основным критерием является логическая цепочка в виде: проблема – решение – ценность – приоритет.

### Векторы атак

**Критические уязвимости:**
- CWE-287 (Improper Authentication), CWE-284 (Improper Access Control)
- CWE-200 (Information Exposure), CWE-319 (Cleartext Transmission)
- OWASP A01:2021 - Broken Access Control

**Возможные атаки:**
- Brute Force / Credential Stuffing
- SQL Injection, XSS, CSRF
- Session Hijacking
- OSINT разведка

### Категории информации

| Категория | Данные | Критичность | Ценность для атакующего |
|-----------|--------|-------------|------------------------|
| ПДн | ФИО, email, телефоны, адреса | КРИТИЧЕСКИЙ | Продажа в даркнете, фишинг |
| Коммерческая информация | Цены, объемы, условия сделок | КРИТИЧЕСКИЙ | Передача конкурентам |
| Технические данные | IP-адреса администраторов | СРЕДНИЙ | Таргетированные атаки |

**Вероятность компрометации:** 90-100% (автоматические сканеры Shodan/Censys легко найдут)

### Последствия

**Финансовые:**
- Потеря конкурентных преимуществ → снижение прибыли на 15-30%
- Штрафы GDPR: до 20M EUR или 4% оборота
- Штрафы ФЗ-152: до 500 тыс. руб.

**Репутационные:**
- Потеря доверия клиентов
- Невозможность участия в тендерах

**Операционные:**
- Ransomware атаки
- Компрометация корпоративной сети

- Должностные лица: 10-20 тыс. руб.

**Дополнительные риски:**
- Проверки Роскомнадзора

ФЗ-224: Штрафы до 1 млрд руб., уголовная ответственность (УК 185.3)

2. Проверить логи на факт утечки
3. Уведомить регуляторы при обнаружении breach

### Приоритизация мер

**P0 - Критические (0-24 часа):**
1. Firewall: блокировка портов 80/443/8080 из WAN (30 мин, 0 EUR)
2. VPN: WireGuard/OpenVPN для доступа к админке (4 часа, 0-1K EUR)
3. Смена паролей админов + password manager (1 час, 0 EUR)
4. IP Whitelisting: ACL для известных IP (2 часа, 0 EUR)
5. Аудит логов за 90 дней (4 часа, 0 EUR)

**P1 - Высокие (1-7 дней):**
1. MFA/2FA: TOTP (Google Authenticator) (2 дня, 0-2K EUR)
2. HTTPS/TLS 1.3 + Let's Encrypt (1 день, 0 EUR)
3. RBAC: Admin/Manager/Viewer (3 дня, 0 EUR)
4. WAF: ModSecurity/Cloudflare (3-5 дней, 0-5K EUR/год)
5. Data masking в UI (2 дня, 0 EUR)

**P2 - Средние (1-4 недели):**
1. SIEM: ELK Stack (2 недели, 5-10K EUR/год)
2. Шифрование БД: TDE/AES-256 (2 недели, 0-5K EUR)
3. SAST/DAST: SonarQube, OWASP ZAP (2 недели, 10K EUR)

### Архитектура

**Текущая (уязвимая):**
```
Internet → Admin Console (Public IP) → Database
```

**Целевая (защищенная):**
```
Internet → WAF → VPN Gateway → Bastion Host → Internal Network →
Reverse Proxy (nginx+TLS) → Admin Console (MFA) → Database (encrypted)
                                                        ↓
                                                      SIEM
```

| Компонент | Решение |
|-----------|---------|
| VPN | WireGuard |
| WAF | ModSecurity/Cloudflare |
| MFA | Google Authenticator |
| SIEM | ELK Stack |
| Encryption | TDE (AES-256) |

### Критические недостатки архитектуры

| Недостаток | Уязвимость | Бизнес-риск | Ущерб |
|------------|-----------|-------------|-------|
| Отсутствие сегментации сети | Прямой доступ из интернета | Компрометация инфраструктуры | Ransomware: 2-5M EUR |
| Broken Access Control (OWASP A01) | CWE-284, CWE-287 | Утечка ПДн, штрафы GDPR | До 20M EUR |
| Information Disclosure | CWE-200 | Утечка коммерческих данных | Потеря конкурентности: 5-10M EUR |
| Отсутствие мониторинга (OWASP A09) | CWE-778 | Позднее обнаружение breach | Увеличение ущерба в 3-5 раз |
| Отсутствие шифрования | CWE-319, CWE-311 | MitM атаки | Compliance: 1-2M EUR |
| Отсутствие Zero Trust | Широкие привилегии | Lateral movement, APT | Полная компрометация: 10-20M EUR |
| Нарушение SSDLC | Множественные CVE | Постоянные инциденты | 1-3M EUR/год |

**Детали:**

1. **Нет сегментации сети:** Админка в публичном сегменте → нарушение Defense in Depth
2. **Broken Access Control:** Нет MFA, IP whitelisting, RBAC → GDPR Art. 32 violation
3. **Information Disclosure:** ПДн/коммерческие данные без маскирования → нарушение data minimization
4. **Нет мониторинга:** Отсутствие SIEM, audit trail → невозможность расследования
5. **Нет шифрования:** HTTP, БД в открытом виде → MitM, кража backup
6. **Нет Zero Trust:** Периметровая модель безопасности → уязвимость к APT
7. **Нарушение SSDLC:** Нет threat modeling, SAST/DAST, Privacy by Design

**Общий потенциальный ущерб:** 40-60M EUR
